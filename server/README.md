# Сервер условий — локальная подготовка, 03.10.2026

Самостоятельный Python 3.12+ сервис без внешних библиотек. GitHub Pages исполняет интерфейс, но не этот сервер. Ничего платного и фонового по умолчанию не включается. Ключи не требуются для чтения сохранённой сводки.

## Проверенный состав

- Чтение публичных страниц Русфишинга и FishingSib с учётом robots.txt, интервалом между запросами и ограничением размера. Без входа и обхода блокировок.
- Пилот: Рыбинское водохранилище, Обь в Новосибирске, Умревинская протока. Рыбинск — неоднозначный запрос: город и конкретный участок требуется уточнять. Каталог России ещё не построен.
- За проход не более пяти тем и 20 новых сообщений за последние семь дней. Две последние темы начального раздела Рыбинского водохранилища; два исходных отчёта FishingSib; одна новая публикация его ленты. У новых публикаций география разрешается из текста; чужое место не присваивается Новосибирску автоматически.
- SQLite: исходные сообщения, версии правок, результаты извлечения, сводки, кеш модели, состояние источников и лимиты. Старые версии сохраняются, но не суммируются как независимые новые свидетельства. База находится за пределами публичного приложения.
- Два отдельных этапа ИИ: извлечение наблюдений и объяснение выбора. У неизвестной даты выезда нет статуса текущей рекомендации; авторы, виды и места не смешиваются; аргументы ссылаются на известные основания. Краткая сводка использует до трёх последних подходящих наблюдений, это ограниченная выборка.
- `GET /api/recon/conditions?place=...&species=...` читает кеш. Открытие сайта и изменение фильтра не вызывают ИИ. Публичных методов запуска сбора/анализа нет.
- Доступны локальный Ollama и отдельный OpenAI API. Модель явно выбирается в настройках; автоматической установки/скачивания нет.

Проведены 22 серверные проверки и пять проверок интерфейсного контракта. Полный путь с ответом модели проверен на контролируемом тестовом транспорте. Реальный сбор сохранил шесть сообщений, из них три свежих из раздела Рыбинского водохранилища; оплаченных запросов ноль. Реальная генерация ни Ollama, ни OpenAI ещё не проверена. ПК и ширины 390/320 px проверены; реальный телефон не проверен.

## Запуск из папки app

```powershell
python server/recon_server.py --serve
python server/recon_server.py --refresh
python server/recon_server.py --export ../data/monitoring/server-export.json
python server/test_server.py
```

При `--serve` адрес по умолчанию `http://127.0.0.1:8787/`. Это временная локальная проверка; автозапуск ОС не настроен. `--refresh` собирает сообщения, а при настроенном провайдере анализирует их. `--export` готовит сводку для проверки и последующей публикации; сам ничего на GitHub не отправляет. В экспорт не попадают исходные тексты, авторские идентификаторы, ключи и личный дневник. Не передавайте SQLite в публичный репозиторий.

## Бесплатный домашний вариант

Рабочая схема: домашний компьютер собирает сообщения → локальная модель анализирует → проверенная краткая сводка публикуется на существующем GitHub Pages. На телефоне доступна последняя опубликованная сводка, даже когда домашний компьютер выключен. Новые сведения в этот момент не обрабатываются. Автоматическая публикация и расписание домашнего процесса ещё не настроены; сначала нужна проверка реальной модели.

Ollama устанавливается отдельно с официального сайта. Используется только локальная модель, её облачные функции следует отключить (`OLLAMA_NO_CLOUD=1`). Наш адаптер обращается исключительно к `127.0.0.1:11434`; сервер ИИ не требуется выставлять в интернет. После установки и выбора загруженной модели в том же окне PowerShell:

```powershell
$env:RECON_AI_PROVIDER='ollama'
$env:RECON_EXTRACT_MODEL='ИМЯ_ЗАГРУЖЕННОЙ_МОДЕЛИ'
$env:RECON_ANALYZE_MODEL=$env:RECON_EXTRACT_MODEL
python server/recon_server.py --refresh
```

16 ГБ RAM, i5-12450H, встроенная графика на текущем ноутбуке позволяют рассмотреть пробу небольшой модели. Это оценка пригодности для испытания, не измеренная скорость или гарантия качества. Первые реальные результаты нужно сравнить с исходными отчётами. Постоянно включённый ноутбук не обязателен: можно обновлять несколько раз в день; отдельный компьютер удобен для работы без участия ноутбука.

## Платный провайдер и размещение

Для OpenAI задаются `RECON_AI_PROVIDER=openai`, `OPENAI_API_KEY`, `RECON_EXTRACT_MODEL`, `RECON_ANALYZE_MODEL`. Ключ хранится только в секретах среды сервера; в чат и JS его не помещать. У API отдельная оплата и перечень поддерживаемых стран; подписка ChatGPT не заменяет API. Эти настройки сейчас не включены.

`.env.example` — образец переменных, **не автоматически загружаемый файл**. Настройки передаются через среду процесса/секреты хостинга. По умолчанию лимит три вызова и 30 000 токенов в сутки; размер входа 14 000 байт, выход 1600 токенов. Резервация лимита атомарная, повторные входные данные кешируются; автоматических платных повторов нет. Это лимит обработки, не фиксированный рублёвый тариф.

`RECON_UPDATE_INTERVAL_SECONDS=0` отключает встроенный планировщик. Включаемый интервал минимум 21 600 секунд. Для постоянного хостинга нужны HTTPS, постоянный диск `RECON_DB_PATH`, ограничения доступа и устойчивый процесс. Dockerfile подготовлен для запуска от непривилегированного пользователя, но контейнер не собран/не испытан. Бесплатный спящий хостинг без постоянного диска для этой базы не подходит.

Погода: функция проверки единиц/возраста опорной точки подготовлена, но в реестре пока нет координат, поэтому погодное сопоставление не включено. Гидропосты, правила, доступ и национальный поиск ещё не подключены. Fisher.spb.ru и Fishing.ru находятся в общем реестре ручной/чатовой очереди, но серверных адаптеров для них пока нет.
