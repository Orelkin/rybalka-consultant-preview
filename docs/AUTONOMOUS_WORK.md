# Автономная работа — 02.10.2026

Пользователь разрешил продолжать без его участия, двигаться к завершающей стадии и сообщать о завершённых этапах. Его новое решение дополняет прежний ROADMAP: версия для ПК имеет отдельную широкую компоновку по присланному макету; мобильное оформление сохраняется.

## Порядок

1. Desktop-оболочка и главная по `docs/design/desktop/approved-reference.jpg`: левое меню, верхняя строка поиска/региона/условий, широкая рабочая область, панели и быстрые переходы. Настоящие значения и ясные состояния отсутствия данных вместо чисел из картинки.
2. Завершить единый стандарт содержания рыб: следующий вид — сом, далее небольшие партии по приоритетам регионов. Исследования, практика и личный опыт различаются; каждый новый пакет проверяется и фиксируется. Проверка изображений отдельная, не повторная генерация всего каталога.
3. Личный слой: подтвердившиеся прежние выезды, включая нулевые; объединение с дневником не должно дублировать записи или стирать личные данные. Неполные сведения остаются неполными.
4. «Куда ехать»: объяснимый выбор участка и метода, источники погоды/воды, возраст данных, недоступность и ограничения. Начать с имеющегося live-пилота; не подменять температуру воды воздухом.
5. Привести оставшиеся разделы и навигацию к общему desktop/mobile оформлению, проверить основные пользовательские сценарии, производительность и восстановление из копии. Подготовить версию для финального просмотра.

## Режим

Глубину разбора и объём операций выбирать по правилу экономии токенов пользователя от 02.10.2026 в [OPERATING_MODEL.md](OPERATING_MODEL.md#экономия-токенов). После сложных решений возвращаться к короткому исполнению; обязательные проверки сохранять.

Одна законченная задача или небольшая партия за рабочий этап. До начала сверять PROJECT_STATE, GitHub main и собственную очередь; не повторять общий поиск. Использовать сохранённые источники и инструменты. Не создавать другой контур разработки и не писать другим чатам. Не привлекать агентов без отдельного разрешения.

Каждый этап: содержательная проверка → сохранённый артефакт/commit → WORK_LOG/PROJECT_STATE → проверка публикации при выпуске. Согласованные проверенные изменения приложения можно интегрировать в тот же main и GitHub Pages. Не публиковать приватные архивы или координаты. Полные ZIP сохранять по завершении существенных этапов; не создавать новый полный архив на каждую мелкую правку.

Сохранять исходные материалы, `sources/` только читать. Сведения с макета о прогнозах, рыбалках, датах и статистике не считать фактами. Не сообщать о биологической проверке или полном прочтении, если они не выполнены.

Сообщать коротко только о завершённом этапе, препятствии или необходимости участия пользователя. Проверка реального телефона остаётся пользовательской задачей и не считается выполненной при моделировании ширины экрана. Автономный запуск останавливается при готовности версии к финальному просмотру, при команде пользователя «стоп/пауза» или необходимости незаменимого участия пользователя; незавершённые задачи сохраняются в очереди.
