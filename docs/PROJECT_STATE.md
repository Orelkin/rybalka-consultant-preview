## 4. Изображения рыб

Изображения переведены на локальное хранение.
Каталог использует lazy loading и локальные thumbnails.
В актуальном реестре 62 подводные иллюстрации и одно сохранённое справочное изображение каспийской иглы.
Щука имеет принятый из main статус `verified_species_visual` и `visual_verification.status = VERIFIED`. Остальные 62 записи требуют отдельной видовой проверки. В этой рабочей сессии новая биологическая верификация не проводилась.
Локальный сборщик сохраняет результат проверки только при совпадении вида, таксона, пути, SHA256 и размера файла; замена изображения требует новой проверки.

Важно: визуальная/UI-проверка не равна биологической видовой верификации.
Статусы `needs_species_review` / `catalog_mapping_unverified_art` сохранять до отдельной проверки морфологии по надёжным референсам.

Не регенерировать весь набор без причины. Проверка идёт по схеме:
вид → надёжный референс → морфологическое сравнение → VERIFIED / REVIEW / REPLACE.

## 7. База знаний

Целевая модель знания:
- FACT — научно/официально подтверждённое;
- PRACTICE — проверяемая практика;
- PERSONAL — личный случай пользователя;
- HYPOTHESIS — рабочая гипотеза;
- WEAK/REJECTED — слабое, противоречивое или опровергнутое утверждение.

Каждый важный claim должен иметь:
`claim_id`, вид/регион, источник, evidence grade, область применимости, ограничения и дату проверки.

Научные данные не превращать автоматически в прогноз клёва.
Практическое наблюдение не превращать автоматически в биологический закон.
Личный единичный успех не превращать автоматически в универсальную рекомендацию.

## 9. Фоновые процессы

Фоновые процессы разделяются по ролям:

A. Архив литературы — только последовательный разбор рыболовной литературы и извлечение наблюдений.
B. База знаний — только научные/официальные/региональные исследования, методы и проверка гипотез.
C. Разработка приложения по расписанию — отключена как дублирующий контур. Разработка выполняется только по актуальному ROADMAP через Work/целевую рабочую сессию.

Фоновый исследовательский процесс не меняет UI и код приложения напрямую.
Результаты сначала должны быть структурированы и дедуплицированы.
